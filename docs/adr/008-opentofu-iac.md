# ADR-008: OpenTofu for IaC Output

**Status:** Accepted  
**Date:** 2025-01-01

## Context

Phase 6 adds IaC generation: the planner produces migration plans, and those plans are rendered as infrastructure-as-code that operators can review, modify, and apply. Options considered: Pulumi, AWS CDK, Crossplane, OpenTofu (Terraform fork).

## Decision

Use **OpenTofu** (the Linux Foundation fork of Terraform, MPL-2.0) for IaC output. OpenTofu modules are generated by `packages/iac` from migration plan objects. The generated code targets the appropriate provider (aws, azurerm, google, ibm-cloud).

OpenTofu is chosen over Terraform for licence compatibility (BSL vs MPL-2.0) and over Pulumi/CDK because HCL is the most widely understood IaC DSL among the target users (cloud migration engineers).

The `packages/iac/IaCEngine.generate()` method renders Jinja2 templates to `.tf` files in a temporary directory, runs `tofu validate`, and returns the validated module path.

## Consequences

- **+** Open-source licence (MPL-2.0) compatible with self-hosted distribution.
- **+** HCL is familiar to the target audience.
- **+** OpenTofu provider ecosystem is identical to Terraform; no migration of providers needed.
- **−** Generating valid HCL from Python requires careful template engineering.
- **−** `tofu validate` requires the OpenTofu binary to be available in the worker container.
