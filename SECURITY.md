# Security policy

## Reporting a vulnerability

Please report suspected vulnerabilities privately through GitHub's **Report a vulnerability** (Security → Advisories) on this repository. Do not open a public issue. We aim to acknowledge reports within 3 working days.

## Security model (summary)

| Control | Mechanism | Verified by |
|---|---|---|
| Cloud credentials are readable only by the connector | OpenBao AppRoles: `aether-api` = create/update/delete, `aether-connector` = read. The root token is revoked after bootstrap. | `aetherctl selftest`, integration tests |
| Credentials never reach logs, the DB, workflow history or the UI | Secrets go only to OpenBao. Workflows carry IDs. Structured-log redaction. Validation errors never echo input. | Integration tests (`test_access_key_secret_goes_to_openbao_only`) |
| Tenant isolation | Per-workspace roles; PostgreSQL RLS scoped per transaction; the runtime role is non-superuser and `NOBYPASSRLS` | `test_rls_isolates_workspaces`, `selftest` |
| Tamper-evident audit | Hash chain with an advisory lock; INSERT/SELECT-only grants; a trigger blocks UPDATE/DELETE/TRUNCATE | `test_tampering_is_detected`, `/api/v1/audit/verify` |
| Least-privilege cloud access | Generated read-only IAM policy (no `ReadOnlyAccess`). ExternalId generated by the platform. The connection test flags excess permissions via policy simulation. | Unit tests; connection test |
| Network segmentation | Internal Docker networks. Only the edge publishes ports. Only the connector has egress. | `selftest` |
| Container hardening | Non-root users, read-only rootfs, `cap_drop: ALL`, `no-new-privileges`, resource limits, no Docker socket | `lint_compose.py` in CI |
| Supply chain | Pinned versions and lockfiles, Trivy gate, gitleaks, SBOM + provenance, cosign signatures on releases | CI |
| Identity | Keycloak OIDC (PKCE, S256), brute-force protection, password policy, MFA for the first admin, short-lived access tokens | Realm config |

## Known limitations (v0.1)

- **Single host.** No high availability; see PROJECT_PLAN §19.5.
- **Plain HTTP between internal services** (all on internal Docker networks). Enable TLS on OpenBao's listener if your threat model requires it.
- **Credential encryption relies on OpenBao.** Database-at-rest encryption depends on host disk encryption.
